# CLAUDE.md

## Architecture overview

`tfdo` is a Terraform/OpenTofu lifecycle CLI that adds multi-directory orchestration, retry, and CI scaffolding on top of the raw `terraform`/`tofu` binary.

### Entry point and CLI

- `tfdo/cli.py` — imports all `cmd_*` modules from `_internal/` subpackages; each import registers its Typer subcommand with the shared `app` in `_internal/typer_app.py`.
- `tfdo/_internal/typer_app.py` — defines the root `app` and the `@app.callback()` that builds `TfDoSettings` from CLI flags/env vars and stores it in `ctx.obj`.
- Public API surface is re-exported from the top-level modules (`tfdo/config.py`, `tfdo/core.py`, etc.); these are generated by `pkg-ext`.

### Settings and configuration layers

- `TfDoSettings` (`_internal/settings.py`) — runtime settings loaded from `TFDO_*` env vars (e.g. `TFDO_BINARY`, `TFDO_WORK_DIR`). Passed as `ctx.obj` through the Typer context tree.
- `TfDoConfig` (`_internal/config/config_model.py`) — project config stored in `tfdo.yaml` files. Multiple layers are stacked: repo root → env directory → run directory. `load_config_layers()` in `_internal/config/config_file.py` walks from `work_dir` up to the git root collecting layers.
- `ResolvedConfig` (`_internal/config/config_resolution.py`) — merges the stacked `TfDoConfig` layers into one effective config for a given run directory.

### Run directory discovery

- The `run_dir_discovery` field in `TfDoConfig` is a pattern string (default `envs/{env}/{run_dir}`) with named selectors in `{braces}`.
- `_internal/config/discovery_pattern.py` — parses patterns and matches filesystem paths against them, extracting selector values as a `dict[str, str]`.
- `_internal/run/discovery.py` — walks the repo, finds directories matching the pattern that also contain a `terraform { backend {} }` block, and produces `DiscoveredRunDir` objects.
- The first selector must always be `{env}`.

### Orchestration (multi-directory runs)

- `_internal/run/orchestration.py` — central orchestrator that discovers run dirs, resolves config + var files, injects tags, and executes plan/apply/destroy across them (concurrently via `run_pool`).
- `_internal/run/filtering.py` — tag-based and selector-based filtering of discovered run dirs.
- `_internal/run/var_file_resolution.py` — resolves `.tfvars` files from config layers.
- `_internal/run/tags_injection.py` — injects common tags into HCL files.

### HCL manipulation

Several modules handle HCL read/write without going through the Terraform CLI:
- `_internal/hcl_entity_parser.py` — parses HCL into typed entities (`TfResource`, `TfVariable`, `TfProvider`, etc.) using `python-hcl2`.
- `_internal/hcl_roundtrip.py` — AST-level add/update/delete of HCL blocks while preserving formatting.
- `_internal/hcl_run_dir_gen.py` — generates/merges run-directory HCL content.
- `_internal/hcl_run_dir_merge.py` — merges generated HCL into existing files.

### Provider hints

- `_internal/config/provider_hints.py` and `provider_hints.yaml` — a registry mapping provider names to auth bundles (env vars → tf vars). Used by `check` and `inspect` to validate provider configuration. `VariableMapping` has an optional `provider_attr` field for direct attribute mapping.

### Other subcommands

| Subpackage | Purpose |
|---|---|
| `_internal/core/` | Thin wrappers over `terraform init/plan/apply/destroy` with retry logic (`executor.py`) |
| `_internal/check/` | Validates run dirs (fmt, validate, tflint, provider config) |
| `_internal/schema/` | Downloads and caches Terraform provider schemas |
| `_internal/inspect/` | Inspects HCL resources against cached schemas |
| `_internal/new/` | Scaffolds new run directories |
| `_internal/copy/` | Copies env configurations |
| `_internal/boot/` | Bootstrap S3 backend and remote state |
| `_internal/sync/` | Syncs justfile sections and GitHub Actions workflows |
| `_internal/hooks/` | Lifecycle hook registration and execution |
| `_internal/cache/` | Module caching utilities |

### Key dependencies

- `ask-shell` — shell execution utilities and console configuration (workspace-local package)
- `model-lib` — Pydantic model utilities including `StaticSettings` base class (workspace-local package)
- `python-hcl2` — HCL2 parsing
- `typer` — CLI framework
- `pydantic` — data models throughout
